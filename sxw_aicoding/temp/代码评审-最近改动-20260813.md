## 三、发现的问题

### 中等（建议修复 / 功能未闭环）

**M1. 已跟踪 `filePath`，但「保存」仍每次弹对话框，未打通原地保存**
- 位置：`src/renderer/components/Toolbar.tsx:57-67`（`handleSave`）、`src/main/ipc.ts` `FILE_SAVE` 处理器
- 现状：本次改动新增了 `filePathByMode` 全链路跟踪、保存成功后 `setFilePath(saved.path)`，但 `saveFile` 仍无条件 `showSaveDialog`。即打开 `a.json` 后按保存，仍走「另存为」弹窗，而非直接覆盖当前文件。
- 影响：文件名跟踪能力已具备，却没用于实现 Cmd+S 原地保存，功能闭环缺一环，用户体验不一致。
- 建议：新增「保存到当前路径」通道（有 `filePath` 时直接 `writeFile`，无则弹「另存为」），或在此明确说明「始终另存为」是产品预期。

**M2. 标题缺少「已修改」态；文件被外部移动/删除后代理图标仍指向旧路径**
- 位置：`src/main/windowManager.ts:76`（`setRepresentedFilename`）、`Toolbar.tsx:171` 标题渲染
- 现状：标题只展示文件名，内容被大量编辑后无 dirty 指示（常见编辑器会显示圆点/`*`）；`setRepresentedFilename` 也不校验路径是否仍存在。
- 影响：用户可能误以为磁盘内容与编辑器一致。属 UX 缺口，非崩溃。
- 建议：接入 rawText 与已保存内容的对比，标题加修改标记；可选地对不存在的路径清空代理图标。

### 轻微（命名 / 注释 / 一致性）

**L1. `setWindowTitle` 语义已漂移，名字有误导**
- 位置：`src/preload/index.ts`、`src/renderer/types/electron.d.ts`、`src/renderer/App.tsx:66`
- 现状：该 API 现在上报的是 `{ filePath, theme, editorMode }` 状态，标题实际由主进程 `composeTitle` 组装。名字仍叫 `setWindowTitle`。
- 建议：更名为 `reportWindowState` / `syncWindowState`，避免后续维护者误解为「直接设置标题」。

**L2. `getFocusedWindowConfig` fallback 注释与行为不符**
- 位置：`src/main/windowManager.ts:91-93`
- 现状：注释写「取最近活跃窗口的配置」，实际是 `[...windows.values()].pop()`，即**最后注册**的窗口，而非最近聚焦的窗口。
- 建议：修正注释，或维护一个 `lastFocusedId` 真正实现「最近活跃」。

**L3. 取文件名的实现两处不一致**
- 位置：`src/renderer/components/Toolbar.tsx:54` 用 `filePath.split('/').pop()`；`windowManager.ts:33` 用 `basename()`
- 现状：macOS 单目标下二者等价，但实现风格不统一。
- 建议：统一（例如主进程回传 `name`，或前端复用同一工具函数），降低跨平台/维护风险。

**L4. theme 变化会触发整轮标题重算**
- 位置：`src/renderer/App.tsx` 上报 `useEffect` 依赖 `[currentFilePath, editorMode, theme]`
- 现状：主题切换与标题无关，却也会走 `setWindowTitle → recomputeAllTitles → onChangeCallback`（菜单/窗口列表重建）。
- 影响：多余重算，窗口数很少时可忽略。
- 建议：如需精简，可将 theme 上报与标题上报拆分（非必需）。

## 四、亮点（实现质量）

- **灯箱 id 隔离**：`svg.split(domId).join(`${domId}-zoom`)` 整串替换 token，`<style>` 选择器 / marker id / `url(#...)` 均由该 token 派生，替换后自洽，彻底避免与内联图表重复 id。注释解释到位（`MermaidLightbox.tsx`）。
- **复用渲染结果**：灯箱直接复用已渲染 SVG 字符串，不重复调用 `mermaid.render`，性能友好。
- **缩放/拖拽交互专业**：滚轮以光标为锚点缩放、`setTransform` 函数式更新防止连续事件丢步、`wheel` 手动注册 `passive:false`、指针捕获拖拽、双击在适配/1:1 间切换。
- **文件路径按模式隔离**：`filePathByMode` 且**不并入 config**，从而不会被 `Cmd+N` 新窗口继承——这是明确的设计目标且实现正确（`windowManager.ts:13`、`uiSlice.ts` `setFilePath`）。
- **重名消歧**：仅当与其他窗口文件名重复时才追加窗口编号；文件名/模式/开关窗口都触发全局重算；`isDestroyed()` 守卫齐备。
- **无障碍**：Mermaid 图容器 `role="button"` + `tabIndex` + `aria-label` + Enter/Space 键盘支持。
- **类型链路一致**：`saveFile` 返回值由 `boolean` 改为 `{ path } | null`、`setWindowTitle` 入参改为对象，preload / `electron.d.ts` / 主进程三处同步改齐，`npm run build` 通过。
